# Acceptance handoff

Read the canonical Evidence Manifest and version record. Summarize scope, environment anchors, passed, failed, blocked, and skipped cases, known limitations, and the report path. Include only evidence-backed conclusions and never turn partial coverage into a pass. Produce a ready-to-send draft and a recipient/permission checklist. This public skill does not grant access, upload assets, or send messages; perform those actions only through a separately configured integration with explicit authorization.

For source handoff, retain task/document revisions, exact branch and commit, covered files, pending gaps and fresh remote-verification evidence. Reuse a reachable commit that covers the scope and reuse an identical snapshot; changed materials need a new snapshot, not erased history. An initial requirement without source needs no empty commit. Check task-related staged, unstaged and untracked files without clearing unrelated work. Reuse existing action-specific authorization within its scope; distinguish a gate rejection from missing user permission. Do not equate document-link registration with a verified document revision.
