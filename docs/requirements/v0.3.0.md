# DeliveryGuard v0.3.0 harness guidance refresh

DeliveryGuard v0.3.0 promotes additional provider-neutral guidance learned from a live delivery harness while preserving the public clean-room boundary. The CLI command surface and JSON Schema contracts remain unchanged.

## Requirements

### Recording-based diagnosis

- Install a `deliveryguard-video-diagnosis` skill for visual, timing, and interaction problems shown in recordings or accessible players.
- Prefer an original local media file, then an authorized player, and use bounded screen capture only when its privacy scope can be constrained.
- Provide a local Node.js helper that uses already-installed FFmpeg and FFprobe to create a temporary frame index with actual decoded-frame timestamps.
- Review the full observed range coarsely and relevant state transitions densely; require actual visual inspection rather than treating generated metadata as completed review.
- Keep visible pixels separate from touch, network, server, persistence, and root-cause claims. Route request evidence to the request-diagnosis skill.
- Do not install dependencies, bypass access controls, overwrite source media, upload media, reproduce business actions, or persist frames without the corresponding authorization.

### Verification and acceptance routing

- Route focused page, API, defect, or small-case verification separately from formal full-version acceptance.
- Do not create or update a full-version Evidence Manifest, report, or pass status for a local verification request.
- Route formal acceptance through complete document-to-requirement-to-case coverage and route report-only handoff through the existing handoff skill.
- If one device, account, environment, or tool dependency is blocked, preserve that layer as blocked while continuing otherwise independent checks.

### Public harness contract

- Keep tracked instructions and package metadata limited to shared project rules and explicitly supported tooling.
- Keep personal skills, branches, local debuggers, and private automation outside installed project contracts by default.
- Increase the bundled skill suite from 19 to 20 skills and keep repository and npm-template copies byte-for-byte identical.
- Scan every textual skill resource, including scripts, for private coordinates and credentials.

## Non-goals

- No business-specific SKU, route, repository, branch, device, account, document, or environment rule.
- No source-project script or internal attachment workflow is copied into the public package.
- No hash-chain run ledger or implicit write is added to `deliveryguard check`.
- No CLI command, JSON Schema, automatic deployment, messaging, Git push, or package publication behavior is added.
