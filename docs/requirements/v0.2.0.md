# DeliveryGuard v0.2.0 diagnosis and real-device skills

DeliveryGuard v0.2.0 adds two public, provider-neutral Codex skills while leaving the CLI commands and JSON Schema contracts unchanged.

## Requirements

### Request diagnosis

- Install a `deliveryguard-request-diagnosis` skill for page, API, and multi-service request failures.
- Prefer trace and span evidence and identify the first failing boundary instead of inferring a root cause from the final error.
- Record user-visible state, transport status, application or business-envelope status, and downstream status separately.
- When no trace identifier exists, allow bounded network capture, time-window log correlation, and comparison with a healthy sibling request, while lowering confidence and naming unverified assumptions.
- Classify the likely cause as routing, authentication or authorization, validation, code, data, dependency, deployment, or infrastructure.
- Keep diagnosis read-only unless the user separately authorizes a repair or external change.

### Real-device testing

- Install one `deliveryguard-real-device-test` skill that routes to Android or iOS guidance.
- Ask the user to choose Android or iOS only when the platform cannot be inferred from the request or current device context.
- Route Android work to a Mobile MCP runbook that rediscovers devices, applications, and live screen elements for every run and captures appropriate visual or crash evidence.
- Route iOS work to a clean-room Appium/XCUITest runbook covering device discovery, signing prerequisites, isolated tooling, WebDriverAgent, optional RemoteXPC, native smoke testing, WebView discovery, H5 assertions, and cleanup.
- Judge device connectivity, native automation, WebView inspectability, and H5 assertions independently. Success at one layer must not imply success at a later layer.
- Require current, explicit authorization before installing or uninstalling applications, changing signing or system settings, starting a privileged tunnel, entering credentials, or mutating business data.

### Packaging and public boundary

- Increase the Codex skill suite from 17 to 19 skills.
- Keep `.agents/skills/` byte-for-byte aligned with `templates/codex/.agents/skills/`.
- Package the Android and iOS runbooks as conditionally loaded references under the real-device skill.
- Exclude business names, private hosts, application schemes, package or bundle identifiers, device identifiers, signing-team identifiers, device names, accounts, user identifiers, private environment coordinates, absolute user paths, and personal screenshots.
- Do not bundle a device service, private adapter, fixed device configuration, or business-specific script.

## Non-goals

- No CLI command or JSON Schema change.
- No real-device operation as part of this version preparation.
- No automatic Git, deployment, GitHub Release, or npm publication behavior is added to the product. Release operations remain separately authorized.
